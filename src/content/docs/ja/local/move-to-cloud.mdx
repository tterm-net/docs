Mac から `ssh` で接続しているサーバーは、tTerm Web、スマートフォン、サインインしたどのコンピューターからでも開けるようにできます。[Mac 版 tTerm](../mac/) の **クラウドへ移行** は、サーバーを 1 台ずつ、選んだ方法でアカウントに移します。**移行** を押すまで、何も移されません。

## 場所

Mac 版 tTerm にサインインし、サイドバーの下のアカウントを開いて、**サインアウト** のすぐ上にある **クラウドへ移行** を選びます。**⌘K** でも見つかります。

<Screenshot name="move-menu" alt="サイドバーのいちばん下にあるアカウントメニュー：「サインアウト」のすぐ上に「クラウドへ移行」（「この Mac のサーバーと鍵」）があります。" />

## 見つかるもの

**この Mac のサーバー** には、`~/.ssh/config`、`known_hosts`、そしてこの Mac の tTerm のターミナルで実行した `ssh` コマンドから見つかったサーバーが並びます。それぞれについて、ssh 自身が使うアドレス、ポート、ユーザー、鍵、踏み台サーバーを `ssh -G` で調べます。`ssh root@host` や `-p 2222` のように自分で入力したユーザーとポートは、config の設定より優先されます。このとき、Mac はどのサーバーにも接続しません。

最初はすべてのサーバーにチェックが入っています。ただし、github.com のような git のホスト（**git のホスト：開くターミナルはありません**）、**tTerm に追加済み** のサーバー、`known_hosts` にしか記録のないサーバー、[ssh のあとのバー](#ssh-のあとのバー)で **… は今後確認しない** を選んだサーバーは除きます。続いて tTerm Web がクラウドから、各サーバーの SSH ポート、または踏み台サーバーの SSH ポートに接続できるかを確認します。

サーバーの下の **~/.ssh の鍵** には、秘密鍵が並びます。保管庫に入るのは、チェックを入れた鍵だけです。チェックの入ったサーバーが **自分の鍵** でその鍵を使う場合は、鍵にも自動でチェックが入ります。

<Screenshot name="move-found" alt="「クラウドへ移行」：web-01、staging、backup にチェックが入り、それぞれにログイン方法が選ばれています。staging はクラウドから接続できないため「この Mac 経由」です。「tTerm に追加済み」の db-1 と、git のホストである github.com にはチェックが入っていません。「~/.ssh の鍵」では id_ed25519 にチェックが入り、「サーバー 3 台を移行」があります。" />

## 3 つのログイン方法

サーバーごとに方法を選べます。

- **自分の鍵** – 鍵はこの Mac で暗号化されて保管庫に入り、サーバーはそのままです。tTerm Web がクラウドからログインし、そのログインに、保管庫を開いているあなたのデバイス（保管庫を開いたブラウザー、またはこの Mac）が署名します。tTerm Web から接続でき、移せる鍵が `~/.ssh` にあるサーバー向けです。詳しくは [SSH 鍵の保管庫](../../security/keys/)をご覧ください。
- **tTerm のアクセス権** – この Mac が一度ログインし、ログインしたユーザーの `~/.ssh/authorized_keys` に tTerm 専用の行を追加します。あなたの鍵はこの Mac に残ります。以降、tTerm はそのユーザーとして有効期間 2 分の証明書でログインします。[コマンド 1 つで接続したサーバー](../../machines/servers/)と同じ仕組みで、保管庫は必要ありません。`ssh` のあとのバーでは、この方法は **tTerm を許可** という名前です。
- **この Mac 経由** – 何も移しません。Mac がオンラインのあいだ、tTerm がこの Mac に、サーバーへの `ssh` の実行を依頼します。VPN の内側やプライベートネットワークにあって tTerm Web から接続できないサーバーや、鍵をこの Mac の外に出せないサーバー向けです。そのターミナルはクラシックモードで動きます。キー入力はすべて Mac の ssh に直接送られ、ブロックも、危険なコマンドの前の確認もありません。

<Screenshot name="move-ways" alt="サーバーごとのログイン方法：web-01 は「自分の鍵」、staging は「この Mac 経由」で、backup では選択肢（「自分の鍵」「tTerm のアクセス権」「この Mac 経由」）が開いています。その下に、それぞれの方法の説明があります。" />

tTerm がサーバーごとに方法を選んでおきます。鍵を移せるなら **自分の鍵**、tTerm Web からサーバーに接続できないか鍵を外に出せないなら **この Mac 経由**、それ以外なら **tTerm のアクセス権** です。tTerm Web から接続できないサーバーは、**この Mac 経由** しか選べません。クラウドから接続できる踏み台サーバーの先にあるサーバーは、その踏み台サーバーを経由して開きます。

:::note[「この Mac 経由」は Mac がオンラインのときだけ]
Mac 版 tTerm で、**設定** → **このコンピューター** → **tTerm Web とスマートフォンから開けるようにする** をオンにします。すると tTerm は、ウィンドウを閉じてもメニューバーに残り、ログイン時に起動します。
:::

## 「移行」を押したとき

ボタンには、チェックを入れたサーバーの数が **サーバー 3 台を移行** のように表示されます。

- **自分の鍵** には保管庫が必要です。初回は **Touch ID で保管庫を作成** を押し、[リカバリーコード](../../security/keys/#リカバリーコード)を保管しておきます。保管庫がロックされているときは、Touch ID か Mac のパスワードを求められます。この Mac がまだ保管庫を開けるように設定されていなければ、一度だけリカバリーコードを求められます。
- パスフレーズ付きの鍵では、tTerm がパスフレーズを一度だけ尋ねます。パスフレーズはこの Mac から出ません。
- **自分の鍵** では、まずこの Mac がその鍵だけでサーバーにログインし、それから鍵が保管庫に入ります。その鍵で開くサーバーがいくつあっても、保管庫に入るのは 1 回です。**tTerm のアクセス権** では、この Mac が行を追加するためにログインし、tTerm がそれを確かめるため自分の証明書で一度ログインします。
- **自分の鍵** と **tTerm のアクセス権** には、サーバーのホスト鍵が `known_hosts` に記録されている必要があります。新しいサーバーには、先にこの Mac から一度接続してください。

<Screenshot name="move-vault" alt="「自分の鍵」で初めて移行するときの「鍵を保管庫に保存」：id_ed25519 は、この Mac のロック解除と同じ方法で開く保管庫に入ります。「キャンセル」と「Touch ID で保管庫を作成」があります。" />

失敗したサーバーについては、何も保存されません。失敗したサーバーのためだけに保管庫に入った鍵は再び取り除かれ、そうしたサーバーに tTerm が追加した行も削除されます。

## 移行のあと

結果の画面には、tTerm に移ったサーバーの数が **サーバー 3 台中 2 台を tTerm に移行しました** のように表示されます。移ったサーバーはすべて Personal に入ります。各行には、そのサーバーの開き方が **あなたの鍵で開きます**、**tTerm のアクセス権で開きます**、**この Mac 経由（オンラインのあいだ）** のいずれかで示され、横の **ターミナルを開く** でそこにターミナルを開けます。失敗したサーバーには理由が表示され、**再試行** と **変更** があります。**変更** を押すと、そのサーバーだけにチェックが入った一覧に戻ります。一番下には、保管庫に入った鍵、または **移行した鍵はありません。鍵はこの Mac に残ります。** が表示されます。

サイドバーでは、あなたの鍵で開くサーバーの名前の後ろに鍵のマークが付き、Mac を経由するサーバーには **Mac 経由** と表示されます。

<Screenshot name="move-result" alt="「サーバー 3 台中 2 台を tTerm に移行しました」：web-01 は「あなたの鍵で開きます」、staging は「この Mac 経由（オンラインのあいだ）」で、どちらにも「ターミナルを開く」があります。backup は移行されず（known_hosts にホスト鍵がないため）、「再試行」と「変更」があります。id_ed25519 は保管庫に入りました。サイドバーでは web-01 に鍵のマークが付き、staging には「Mac 経由」と表示されています。" />

## ssh のあとのバー

この Mac のターミナルで `ssh` がエラーなく終了すると、そのブロックの下に **droplet をどこからでも開けるように** というバーが、アドレスと鍵と一緒に表示されることがあります。

<Screenshot name="move-strip" alt="この Mac のターミナルの ssh droplet の下：「droplet をどこからでも開けるように」、root@203.0.113.20 と鍵 ~/.ssh/id_ed25519 が表示され、「鍵を保存」「tTerm を許可」「今はしない」「droplet は今後確認しない」があります。" />

- **鍵を保存** – 鍵を移せる場合の **自分の鍵** と同じです。
- **tTerm を許可** – **tTerm のアクセス権** と同じです。
- **今はしない**、または **droplet は今後確認しない**。

tTerm Web から接続できないサーバーでは、バーには代わりに **この Mac 経由で開く** が表示されます。バーはサーバーごとに一度だけ表示され、git のホストや、すでに tTerm にあるサーバーには表示されません。バーから保存したサーバーも Personal に入ります。
