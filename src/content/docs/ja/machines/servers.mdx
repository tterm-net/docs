サーバーは、普通の SSH にコマンド 1 つで接続します。鍵は保管しません。接続のたびに専用の証明書を発行し、有効期間は 2 分、使えるのはこのサーバー 1 台だけです。

お使いの Mac からすでに SSH で接続しているサーバーなら、そこで何も実行せずに、ほかのサーバーとまとめて移せます。詳しくは[クラウドへ移行](../../local/move-to-cloud/)をご覧ください。

## 接続する

<Steps>

1. tTerm Web で **マシンを追加** を開き、**サーバー** を選びます。

   <Screenshot name="add-server" alt="「マシンを追加」ウィンドウで「サーバー」を選んだ状態：サーバーで実行する 1 回限りのコマンドと「コピー」ボタンがあり、tTerm Web がサーバーを待っています。" />

2. コマンドをコピーし、root または sudo が使えるユーザーとしてサーバー上で実行します。

   ```sh title="サーバー上で"
   curl -sSL https://connect.tterm.net/s/<token> | sudo sh
   ```

3. スクリプトが終わればすぐにサーバーがプロジェクトに現れます。通常は 1 分ほどです。クラウドは自分でサーバーにサインインして確認し、システム、アドレス、シェルといったマシンの情報を読み取ります。

</Steps>

:::caution[コマンドは 1 回だけ使えます]
このコマンドは 1 回だけ、これから 10 分間だけ使えます。間に合わなかったときは **新しいコマンドを取得** を押してください。
:::

## スクリプトが行うこと

- パスワードなしのユーザー `tterm` を作ります。tTerm の Telegram ボットがすでに作っていた場合は、それを使います。
- 有効期間 2 分で、このサーバー 1 台のためだけに発行される証明書で、クラウドが `tterm` としてサインインできるようにします。サーバーに鍵は残りません。
- サーバーを管理できるように、`tterm` に sudo を与えます。取り消すのはコマンド 1 つです。
- `sshd_config` には一切触れず、ポートも開けません。二度実行しても安全です。

信頼の設定は、ユーザー `tterm` の `authorized_keys` に書く 1 行だけで、サーバーごとに別の行になります。

```text title="~tterm/.ssh/authorized_keys"
cert-authority,principals="m-…" ssh-ed25519 AAAAC3NzaC1lZDI1NTE5… tterm-web ca-…
```

:::tip[NAT の内側にある、または外から SSH で入れないサーバー]
クラウドは SSH でサーバーにサインインするので、SSH のポートが外から届く必要があります。届かない場合は、[コンピューター](../computers/)と同じようにサーバーにエージェントを入れてください。接続は内側から行われます。
:::

## サーバーを削除する

プロジェクトのページでサーバーの横の ⋯ を押し、**マシンを削除** を選びます。クラウドはそのサーバーへのサインインをやめ、サーバー上から自身のアクセス権を取り除きます。サーバーが応答しない場合は、続けてそのためのコマンドが表示されます。詳しくは[マシンを削除する](../remove/)をご覧ください。

インストーラーが入れたそれ以外のものを削除する方法は、スクリプトの冒頭に書かれています。
