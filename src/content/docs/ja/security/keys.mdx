保管庫は、あなたが自分の SSH 鍵で接続するサーバーのために、その鍵を保管します。鍵はデバイスの外に出る前にそのデバイスで暗号化され、保管庫を開けるのはあなただけです。どのブラウザーでも保管庫のパスワードで開けるほか、鍵を保存したデバイスではパスワードなしでも開けます。tTerm が保管するのは暗号化された鍵と、各鍵の公開鍵部分とフィンガープリントだけで、保管庫を開くことも、鍵を読むこともできません。保管庫は **設定** → **SSH 鍵** にあります。

## サーバーがあなたの鍵で開く仕組み

[Mac 版 tTerm](../../local/mac/) から **自分の鍵** でサーバーを移すか、`ssh` のあとに表示されるバーで **鍵を保存** を押すと、そのサーバーはあなたの鍵で開くようになります。詳しくは[クラウドへ移行](../../local/move-to-cloud/)をご覧ください。そのサーバーでターミナルを開くと、開いたデバイス自身が、そこで開いている鍵でログインに署名します。ブラウザーで開いたターミナルならそのブラウザー、Mac 版 tTerm で開いたターミナルなら Mac 版 tTerm です。ほかのデバイスには、お使いの Mac も含めて、署名を依頼しません。デバイスがその鍵で署名するのは SSH のログインだけで、鍵がデバイスの外に出ることはありません。tTerm は署名を使う前に、鍵の公開鍵部分と照合します。

### 保管庫のパスワード

パスワードは、保管庫を作るときに自分で決めます。12 文字以上で、いくつかの単語をつなげたフレーズがいちばん簡単です。12 文字に満たないあいだは、あと何文字必要かがウィンドウに表示されます。半角英数字と記号以外の文字も使えますが、海外のコンピューターでは、キーボードの設定によっては入力できないことがあります。

<Screenshot name="vault-password" alt="「保管庫のパスワードを作成」：id_ed25519 はこのブラウザーの中で暗号化されて保管庫に入り、このパスワードでどのブラウザーでも開けます。「パスワード」と「パスワード（確認用）」には点で伏せたパスワードが入力されていて、「表示」ボタン、「12 文字以上」というヒント、「一致しています」があります。tTerm はこのパスワードを知らず、復元もできません。「キャンセル」と「保管庫を作成」があります。" />

パスワード自体は、どこにも送られません。ブラウザーまたは Mac がパスワードから鍵を作り、tTerm は、パスワードを知っていることを示したデバイスにだけ、保管庫の暗号化された鍵を渡します。tTerm はパスワードを知らず、復元することもできません。パスワードマネージャーに保存しておいてください。

パスワードが違う場合はそう表示され、あと何回試せるかも示されます。1 時間以内に 10 回間違えると 1 時間、1 日以内に 30 回間違えるとその日が終わるまで、試せなくなります。次にいつ試せるかは、ウィンドウに表示されます。

**パスワードをお忘れですか？** パスワードなしで保管庫を開けるデバイスで、新しいパスワードを設定してください。お使いの Mac なら、Mac 版 tTerm の **設定** → **SSH 鍵** → **パスワードを変更** で、Touch ID を使って設定します。鍵を保存したブラウザーなら、同じく **設定** → **SSH 鍵** で設定できます。そのようなデバイスがない場合、保管庫にある鍵はもう開けません。tTerm にも開けません。鍵そのものは、通常はお使いの Mac の `~/.ssh` に残っています。

<Screenshot name="vault-forgot" alt="「保管庫のパスワードをお忘れですか？」：tTerm がパスワードを教えることはできませんが、パスワードなしで保管庫を開けるデバイスでは、新しいパスワードを設定できます。お使いの Mac では、Mac 版 tTerm で「設定」の「SSH 鍵」を開き、「パスワードを変更」を押して Touch ID で確認します。鍵を保存したブラウザーでも設定できます。そのようなデバイスがなければ、鍵はもう開けません。「OK」があります。" />

## 別のブラウザーで開く

鍵を保存していないブラウザーでは、**設定** → **SSH 鍵** に **保管庫は閉じています** と表示され、**保管庫のパスワード** の欄があります。あなたの鍵で開くサーバーでは、ターミナルが作られる前に表示されるカードに、同じ欄があります。詳しくは[保管庫を待つサーバー](#保管庫を待つサーバー)をご覧ください。

<Screenshot name="vault-open" alt="保管庫をまだ開いたことのないブラウザーでの「設定」→「SSH 鍵」：「保管庫は閉じています」とあり、鍵を開けるのは保管庫のパスワードだけで、鍵はこのブラウザーの中で開きます。「保管庫のパスワード」の欄には点で伏せたパスワードが入力されていて、「表示」と「鍵を開く」、その下に「パスワードをお忘れですか？」があります。さらに下には、「保管庫のパスワード」の行、2 つの鍵、パスワードなしで保管庫を開けるデバイスが表示されています。" />

- **保管庫のパスワードを入力して**、**鍵を開く** を押します。鍵はこのブラウザーの中ですぐに開きます。
- **Mac 版 tTerm で承認する** こともできます。ほかの人のコンピューターで使うと便利で、そこではパスワードを入力せずに済みます。Mac 版 tTerm で保管庫を開ける場合は、欄の下に、その Mac の名前が入った **MacBook-Pro で承認** があります。これを押すと **このブラウザーで鍵を開く** ウィンドウが開き、すぐにその Mac へ依頼が送られます。Mac には、どのブラウザーが依頼しているか、いつ、どのアドレスからサインインしたかを示すウィンドウが表示されます。両方の画面に同じ 6 桁の数字が表示されるので、一致する場合だけ **Touch ID で許可** を押してください。**心当たりがない** を押すとそのブラウザーのサインインは無効になり、ほかに確認すべきことは **設定** → **デバイス** に表示されます。依頼は 5 分で期限が切れます。**代わりにパスワードを入力** を押すと、パスワードの欄に戻ります。

パスキーで鍵を保存できるブラウザーでは、続いて tTerm が、このブラウザーに鍵を保存するかどうかを尋ねます。保存すると、次回からこのブラウザーではパスワードを求められません。**Touch ID で保存**（または Windows Hello、パスキー）を選ぶか、自分のものではないコンピューターなら **今回のみ** を選びます。その場合、鍵はタブを閉じたときに閉じ、しばらく使わなかったときも自動で閉じます。

<Screenshot name="vault-keep" alt="保管庫のパスワードを入力したあと：「このブラウザーで鍵を開きました」。Touch ID でこのブラウザーに鍵を保存すれば、次回からは Touch ID だけで済みます。ほかの人のコンピューターなら「今回のみ」を選びます。「今回のみ」と「Touch ID で保存」があります。" />

tTerm Web 0.1.26 より前に作られ、まだパスワードのない保管庫は、これまでどおりに開きます。**設定** → **SSH 鍵** で **開く** を押すと **このブラウザーで鍵を開く** が表示されます。そこには、Mac に承認してもらうための **ここで保管庫を開けるよう依頼** と、**リカバリーコード** の欄および **開く** があります。

Mac 版 tTerm では、まだ保管庫を開けるように設定されていない Mac（2 台目の Mac、保管庫をブラウザーで作った場合、サインアウトしてもう一度サインインしたあと）に、**この Mac は、まだ保管庫を開けるように設定されていません** と表示されます。その Mac では一度だけ、Touch ID なしで、保管庫のパスワードを使って開きます。以降は、Touch ID か Mac のパスワードで開けます。

## 鍵が開いている場所

保管庫があれば、あなたのコンピューター、あなたの鍵で開くサーバー、Mac 経由のサーバーが開くのは、あなた自身が鍵を開いたデバイスだけです。鍵を開く方法は、保管庫のパスワード、鍵を保存したブラウザーでの Touch ID、または Mac 版 tTerm での承認です。ここでいうコンピューターとは、tTerm のエージェントを入れた macOS や Linux のマシンと、Mac 版 tTerm を入れた Mac のことです。これらのマシンを開くには、メールのコードで tTerm にサインインするだけでは足りません。そのため、誰かがあなたのメールに入り込んでも、これらのマシンからは何も得られません。お使いの Mac が起動していて、そこで保管庫が開いているあいだも同じです。tTerm 専用の行があるサーバー（コマンド 1 つで接続したサーバーや、**tTerm のアクセス権** で移したサーバー）は、これに含まれず、サインインだけで開きます。保管庫がない場合や、保管庫にパスワードも鍵もない場合は、この仕組みで閉じるものはありません。

鍵が開いていないデバイスでは、こうしたマシンには **+** の代わりに錠前のマークが付き、そのターミナルとログは薄く表示されて、それぞれに錠前のマークが付きます。それらのタブの先頭にも、同じマークが付きます。そのデバイスには、こうしたマシンのものは何も届きません。ターミナルの画面も、検索や入力行の履歴に出るコマンドも、ログも届きません。錠前のマーク、ターミナル、ログのいずれかをクリックすると、タブにカードが表示されます。カードには閉じている理由が示され、その場で、このデバイスに合った方法で鍵を開けます。**保管庫のパスワード** の欄か、鍵を保存したブラウザーなら **Touch ID で開く**、または **MacBook-Pro で承認** です。そのあとは次のとおりです。

<Screenshot name="closed-sidebar" alt="Anna の鍵が開いていないデバイスのサイドバー：MacBook-Pro、web-01、staging には「+」の代わりに錠前のマークが付き、それらのターミナル shop と deploy、そしてそれぞれのログは薄く表示されて、どれにも錠前のマークが付いています。Client X の db-1 はいつもどおりです。ポインターは web-01 の錠前のマークの上にあり、「このデバイスでは鍵が開いていません。開く」と表示されています。" />

- 錠前のマーク：カードに代わって、そのマシンで新しいターミナルが開きます。
- すでに動いているターミナル：今の状態から表示され、新しいターミナルは作られません。
- ログ：ログが開きます。

<Screenshot name="closed-terminal" alt="錠前のマークが付いたタブ「P/web-01 · deploy」：「このターミナルは、このデバイスでは閉じています」。web-01 の「deploy」は動いていますが、ここで鍵が開くまで、ここには表示されません。鍵が開けば、今の状態から表示されます。「保管庫のパスワード」、「鍵を開く」、「または MacBook-Pro で承認 · パスワードをお忘れですか？」があります。" />

**マシン** ページでは、こうしたマシンに **このデバイスでは閉じています** と表示され、プロジェクトのページでは、そのターミナルのそれぞれに、フォルダーの代わりに同じ表示が出ます。どちらのページでも、新しいターミナルのボタンには錠前のマークが付き、ターミナルは薄く表示されます。**削除** と **別のプロジェクトに移動** は、まずそのウィンドウの中で鍵を開きます。鍵が開くと、赤い **web-01 を削除** と、マシンを移動するボタンが現れます。

<Screenshot name="closed-machines" alt="鍵が開いていないデバイスでの「マシン」ページ：MacBook-Pro、web-01、staging には「このデバイスでは閉じています」と表示され、それぞれの「ターミナルを開く」に錠前のマークが付いています。それらのターミナル「P/MacBook-Pro · shop」と「P/web-01 · deploy」は薄く表示され、どちらにも錠前のマークが付いています。Client X の db-1 はいつもどおりです。どのマシンにも「削除」があります。" />

どの方法で開いても、鍵が開けば、このデバイスではこうしたマシンがすべて開きます。作られるのは、求めたターミナルだけです。錠前のマークで求められるターミナルは、一度に 1 つです。別の錠前のマークを押すと、前のカードはそのカードに置き換わります。ほかのタブの後ろに残ったカードは、鍵が開くと、ターミナルを作らずに閉じます。[再びロックされるとき](#再びロックされるとき)に挙げた場合など、このデバイスで鍵が閉じると、錠前のマークはすぐに戻り、それらのターミナルのタブはカードに変わります。ターミナル自体は、クラウドで動き続けます。

保管庫のパスワードを変更したり、保管庫から鍵を取り除いたりすると、ほかのデバイスは鍵を開き直します。保管庫に鍵があれば、その鍵を使って自動で開き直し、鍵がなければ、新しいパスワードで開き直します。変更を行ったデバイスは、そのままです。

Mac 版 tTerm では、その Mac 自身のターミナルと、その Mac を経由するサーバーは、これまでどおり鍵を開かなくても開きます。ほかのコンピューターと、あなたの鍵で開くサーバーは、Touch ID か Mac のパスワードで保管庫を開くと、そこで開きます。お使いの Mac が、あなたの鍵でサーバーにログインするのは、Mac 自身のためだけです。ブラウザーがこうしたサーバーを開けるのは、そのブラウザーで鍵を開いたときです。

## 再びロックされるとき

- **ブラウザーの場合** – 8 時間何も操作しなかったとき、tTerm Web を閉じるか再読み込みしたとき、サインアウトしたとき、**設定** → **SSH 鍵** で **ロック** を押したときです。
- **Mac 版 tTerm の場合** – tTerm が動いているあいだは、**ロック** を押すかサインアウトするまで開いたままです。サインアウトすると、Mac は保管庫を開くための設定も忘れます。もう一度サインインしたあと、一度だけ保管庫のパスワードを使って開きます。

## 設定 → SSH 鍵

セクションの上部には、保管庫がここで開いているかどうか、どの方法で開いたか、いつ再びロックされるかが表示されます。その下の **保管庫のパスワード** には、パスワードを設定した日が表示され、横に **パスワードを変更** があります。鍵ごとに 1 行あり、名前、種類、短いフィンガープリント、**開けるサーバー**（まだなければ **この鍵で開くサーバーはまだありません**）、Mac から保存した日またはファイルから追加した日、最後に使った日時（まだなら **未使用**）が並びます。

<Screenshot name="keys" alt="「設定」→「SSH 鍵」：Touch ID で開いた保管庫は「このブラウザーで開いています」となっていて、「ロック」ボタンがあります。「保管庫のパスワード」は、どのブラウザーでも鍵を開けるパスワードで、今日設定されていて、「パスワードを変更」があります。2 つの鍵には、それぞれ種類と短いフィンガープリントが表示されています。「ファイルから鍵を追加」があり、パスワードなしで保管庫を開けるデバイスとして Chrome on macOS が書かれています。" />

- **パスワードを変更** で新しいパスワードを設定すると、すぐに古いパスワードと置き換わり、古いパスワードでは鍵を開けなくなります。お使いの Mac と、鍵を保存したブラウザーでは、これまでどおり開けます。変更に必要なのは、鍵を保存したブラウザーでは Touch ID（または Windows Hello、パスキー）、鍵を保存していないブラウザーでは現在のパスワード、Mac 版 tTerm では Touch ID です。
- **削除** を押すと、確認のあと鍵が保管庫から取り除かれ、tTerm は暗号化されたコピーを削除します。その鍵で開いていたサーバーは tTerm に残りますが、開けなくなります。鍵そのものは元の場所（Mac 上、またはそのファイル）に残ります。保管庫へのほかの変更と同じく、これができるのは鍵が開いている場所だけです。ほかの場所では、tTerm がそう知らせます。
- **ファイルから鍵を追加** はブラウザーにあります。Mac 版 tTerm では、鍵は「クラウドへ移行」と、`ssh` のあとに表示されるバーから入ります。

鍵の下には、パスワードなしで保管庫を開ける場所、つまり鍵を保存したすべての Mac とブラウザーが、こう表示されます：**パスワードなしで保管庫を開けるデバイス：MacBook-Pro · Mac 版 tTerm、Chrome on macOS。ほかのどのブラウザーでも、保管庫のパスワードで開けます。** 1 つもなければ **保管庫は、パスワードでのみ開けます。鍵を保存したデバイスは、まだありません。** と表示されます。

tTerm Web 0.1.26 より前に作られ、まだパスワードのない保管庫では、上部に **保管庫のパスワードを設定** が表示されます。**パスワードを設定** でパスワードを作ると、それ以降はリカバリーコードが使えなくなります。鍵を保存していないブラウザーでは、パスワードの設定にリカバリーコードが必要です。

### 保存できる鍵

Ed25519、ECDSA P-256 と P-384、RSA です。DSA と ECDSA P-521 の鍵、セキュリティキー上の鍵（`sk-…`）は保存できません。セキュリティキー上の鍵は外に出せないため、そのサーバーは [Mac 経由](../../local/move-to-cloud/#3-つのログイン方法)で開きます。

ブラウザーが読み込めるのは、OpenSSH 独自の形式の鍵（パスフレーズ付きも可）と、パスフレーズなしの PEM（PKCS#8、PKCS#1）の鍵で、1 ファイルに 1 つの鍵です。パスフレーズ付きの PEM ファイルは、先に `ssh-keygen -p -f` にそのファイルを指定して、OpenSSH の形式に変換します。Mac 版 tTerm が読み込めるのは、OpenSSH の形式の鍵です。

ブラウザーによっては、Ed25519 鍵で署名できません。その場合は **設定** → **SSH 鍵** にそう表示されます。そうした鍵を使うサーバーは、より新しいブラウザーか Mac 版 tTerm で開きます。

## 保管庫を待つサーバー

鍵が開いていないデバイスでは、あなたの鍵で開くサーバーがターミナルの中で待つことは、もうありません。錠前のマークや新しいターミナルのボタンを押すと、ターミナルが作られる前に、まずカードが開きます。カードには **web-01 はあなたの鍵で開きます** と表示され、その場で鍵を開けます。

- 鍵を保存していないブラウザーでは、カードに **保管庫のパスワード** の欄があります。パスワードを入力して **鍵を開いてターミナルを開く** を押します。その下には、お使いの Mac の名前が入った **MacBook-Pro で承認** と、**パスワードをお忘れですか？** があります。
- 鍵を保存したブラウザーでは、**Touch ID で開く**、**Windows Hello で開く**、**パスキーで開く** のいずれかを押します。その下のリンク **または、保管庫のパスワードを入力** を押すと、代わりにパスワードの欄が表示されます。
- Mac 版 tTerm では **Touch ID で開く** を押します。まだ保管庫を開けるように設定されていない Mac では、そこで一度だけ保管庫のパスワードを入力します。

tTerm Web 0.1.26 より前に作られ、まだパスワードのない保管庫では、これまでどおり、カードにお使いの Mac の名前が入った **MacBook-Pro で承認** か、**リカバリーコードを使う** があります。

そのあとカードに少しのあいだ **このデバイスで鍵を開いています…** と表示され、カードに代わってターミナルが開きます。

それでもターミナルが待つのは、鍵は開いているのに、このデバイスがサーバーの鍵でログインできない場合です。たとえば、鍵が保管庫から取り除かれた場合や、その鍵がこのブラウザーでは開けない場合です。ターミナルには **保管庫はここで開いていますが、id_ed25519 はこのブラウザーでは開けません。** のように理由が表示され、必要なだけ待ち続けます。このデバイスで署名できるようになると、**あなたの鍵で web-01 にログインしています…** と表示され、そのまま開きます。
