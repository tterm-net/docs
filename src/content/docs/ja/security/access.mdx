マシンへのアクセスは簡単に与えられ、同じくらい簡単に取り消せます。お使いの鍵は必要ありませんし、ポートも開けません。

## 有効期間 2 分の証明書

接続のたびに、あなたの名前が入った専用の SSH 証明書を発行します。使えるのはそのサーバー 1 台だけです。そのため、サーバーのログには、誰がサインインしたのか名前つきで毎回残ります。

```text title="/var/log/auth.log"
Accepted publickey for tterm from 203.0.113.24 port 41522 ssh2: ED25519-CERT SHA256:… ID Anna via tTerm Web (…) to web-01 (serial 1042) CA ED25519 SHA256:…
```

## 署名を分離

CA の鍵は、ネットワークにつながっていない別のプロセスにあります。コアはこの鍵を読めず、署名を依頼できるだけです。署名はすべてログに記録されます。

## sshd_config はそのまま

信頼の設定は、1 人のユーザー `tterm` の `authorized_keys` に書く 1 行だけです。何も再起動しないので、自分が入れなくなることはありません。

## Mac から移行したサーバー

Mac 版 tTerm から移行したサーバーは、さらに 2 つの方法で開けます。**自分の鍵** では、[保管庫](../keys/)にあるあなた自身の鍵でサインインします。ログインに署名するのは、保管庫が開いているあなたのデバイスで、サーバーには何も追加されません。**この Mac 経由** では、Mac がサーバーへの `ssh` を実行するので、クラウドからサーバーに届かなくてもかまいません。3 つ目の方法の **tTerm のアクセス権** は同じ有効期間 2 分の証明書で、tTerm の行は `tterm` ではなく、あなた自身のユーザーの `authorized_keys` に入ります。詳しくは[クラウドへ移行](../../local/move-to-cloud/#3-つのログイン方法)をご覧ください。

## 接続は内側からのみ

コンピューターのエージェントは自分から外へ接続するので、受信ポートは必要ありません。削除はコマンド 1 つです。

## 第三者を介さない

tTerm Web のページもターミナルも、EU にある tTerm のサーバーに直接つながります。Cloudflare は DNS として使っているだけで、コマンドを目にすることはありません。

## オープンソース

クラウドとエージェントのコードは AGPL v3 で公開しています。[github.com/tterm-net](https://github.com/tterm-net) にあります。インストールスクリプトは短いので、実行する前にぜひ読んでください。

## アクセスを取り消す

[サーバーを削除](../../machines/remove/)すると、クラウドは自身のアクセス権をそのサーバーから取り除きます。サーバーが応答しない場合は、サーバー上で同じことを行うためのコマンドが表示されます。コンピューターからエージェントを削除するのもコマンド 1 つ、`~/.tterm-web/uninstall.sh` です。保管庫にある自分の鍵は、**設定** → **SSH 鍵** の **削除** で取り除けます。
