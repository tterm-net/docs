서버는 명령 한 줄이면 일반 SSH로 연결돼요. 키는 보관하지 않아요. 연결할 때마다 그 연결만을 위한 인증서에 서명하는데, 이 인증서는 2분 동안만 유효하고 이 서버에서만 쓸 수 있어요.

## 연결하기

<Steps>

1. tTerm Web에서 **머신 추가**를 열고 **서버**를 고르세요.

   <Screenshot name="add-server" alt="‘서버’를 고른 ‘머신 추가’ 창: 서버에서 실행할 일회용 명령과 ‘복사’ 버튼이 있고, tTerm Web이 서버를 기다리고 있어요." />

2. 명령을 복사해서 서버에서 root로, 또는 sudo 권한이 있는 아무 사용자로 실행하세요:

   ```sh title="서버에서"
   curl -sSL https://connect.tterm.net/s/<token> | sudo sh
   ```

3. 스크립트가 끝나는 대로 서버가 프로젝트에 나타나요. 보통 1분이면 돼요. 클라우드가 알아서 서버에 로그인해 확인하고, 시스템, 주소, 셸처럼 어떤 머신인지 읽어 와요.

</Steps>

:::caution[명령은 한 번만 쓸 수 있어요]
앞으로 10분 동안 한 번만 쓸 수 있어요. 시간이 지났나요? **새 명령 받기**를 누르세요.
:::

## 스크립트가 하는 일

- 비밀번호 없는 `tterm` 사용자를 만들어요. 저희 Telegram 봇이 이미 만들어 둔 사용자가 있으면 그대로 써요.
- 클라우드가 `tterm` 사용자로 로그인할 수 있게 해요. 이때 2분 동안만 유효하고 이 서버만을 위해 발급되는 인증서를 써요. 서버에는 키가 남지 않아요.
- 서버를 관리할 수 있도록 `tterm` 사용자에게 sudo 권한을 줘요. 명령 한 줄로 회수할 수 있어요.
- `sshd_config`는 건드리지 않고 포트도 열지 않아요. 두 번 실행해도 안전해요.

신뢰 설정은 `tterm` 사용자의 `authorized_keys`에 들어가는 한 줄이 전부이고, 서버마다 줄이 따로 있어요:

```text title="~tterm/.ssh/authorized_keys"
cert-authority,principals="m-…" ssh-ed25519 AAAAC3NzaC1lZDI1NTE5… tterm-web ca-…
```

:::tip[NAT 뒤에 있거나 외부에서 SSH로 접속할 수 없는 서버]
클라우드는 SSH로 서버에 로그인하기 때문에 서버의 SSH 포트에 외부에서 접속할 수 있어야 해요. 그럴 수 없다면 [컴퓨터](../computers/)처럼 서버에 에이전트를 설치하세요. 그러면 연결이 안쪽에서 열려요.
:::

## 서버 제거하기

프로젝트 페이지에서 서버 옆의 ⋯ 버튼을 누르고 **머신 제거**를 고르세요. 클라우드는 더 이상 서버에 로그인하지 않고, 서버에서 직접 자기 접근 권한을 회수해요. 서버가 응답하지 않으면 서버에서 실행할 명령이 이어서 나타나요. 자세한 내용은 [머신 제거](../remove/) 페이지를 보세요.

설치 스크립트가 설정한 나머지를 제거하는 방법은 스크립트 맨 위에 적혀 있어요.
