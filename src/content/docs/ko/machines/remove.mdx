머신을 제거하면 tTerm Web에서 머신이 빠지고, 그 머신에 대한 tTerm의 접근 권한도 함께 사라져요. 머신이 속한 프로젝트의 소유자와 관리자가 제거할 수 있어요.

## 제거하기

제거할 수 있는 곳은 두 군데예요.

- 사이드바 맨 위의 tTerm 로고를 누르면 열리는 **머신** 페이지에서, 머신 카드의 **제거**를 누르세요.
- 사이드바에서 프로젝트 이름을 누르면 열리는 프로젝트 페이지에서, 머신 옆의 **⋯** 메뉴를 열고 **머신 제거**를 고르세요.

tTerm은 먼저 어떤 일이 일어나는지 알려 주고 확인을 받아요: **web-01 머신을 제거할까요?** 빨간 **web-01 제거** 버튼을 누르면 제거되고, **취소**를 누르면 모든 게 그대로 남아요.

## 제거하면 일어나는 일

- 머신의 터미널이 종료되고, 터미널마다 이유가 표시돼요: **이 터미널은 종료됐어요**, **web-01: tTerm Web에서 제거됐어요.**
- 머신은 사이드바, **머신** 페이지, 프로젝트 페이지에서 빠지고, 머신의 로그도 프로젝트의 **로그** 폴더에서 빠져요.
- 그 머신에서 입력한 명령은 기록에 남아요. [검색](../../features/search/)으로 계속 찾을 수 있고, 머신이 제거됐다는 표시도 함께 나와요. 프로젝트에도 머신을 제거한 내역이 한 줄 남아요.

## 서버

클라우드는 더 이상 서버에 로그인하지 않고, 서버에 있는 `~tterm/.ssh/authorized_keys`에서 자기 줄을 직접 지워요. 그러면 페이지에 이렇게 표시돼요: **tTerm Web에서 web-01 머신을 제거하고, 서버에서 tTerm Web의 접근 권한을 회수했어요.**

서버가 응답하지 않으면, 클라우드가 더 이상 로그인하지는 않지만 그 줄은 서버에 남아요. 이때는 그 줄을 지우는 명령이 창에 나와요. 창을 닫기 전에 명령을 복사해서 서버에서 실행하세요:

```sh title="서버에서"
sudo sed -i '/^cert-authority,principals="m-…" /d' ~tterm/.ssh/authorized_keys
```

창에 나오는 명령은 `principals="m-…"` 값으로 이 서버의 줄만 정확히 가리키고, 파일의 다른 줄은 그대로 둬요. 같은 서버가 다른 프로젝트에도 있다면, 그 프로젝트에서는 자기 줄이 따로 있는 별도의 머신이라서 계속 작동해요.

`tterm` 사용자와 그 sudo 규칙인 `/etc/sudoers.d/tterm`은 제거한 뒤에도 남아요. tTerm 봇이 쓸 수도 있기 때문이에요. 이것까지 지우는 명령은 설치 스크립트 맨 위에 있고, 응답하지 않은 서버의 창에도 나와요:

```sh title="서버에서"
sudo userdel -r tterm && sudo rm -f /etc/sudoers.d/tterm
```

그러면 tTerm 봇의 접근 권한도, 다른 프로젝트에 있는 이 서버의 접근 권한도 함께 사라져요.

### Mac에서 옮긴 서버

[Mac용 tTerm](../../local/move-to-cloud/)에서 **내 키**나 **이 Mac 경유**로 옮긴 서버에는 tTerm이 둔 것이 없어서 지울 것도 없어요. **tTerm 접근 권한**으로 옮겼다면 Mac이 로그인하던 사용자의 `~/.ssh/authorized_keys`에 tTerm의 줄이 있고, 클라우드가 같은 방법으로 지워요. 이런 서버가 응답하지 않으면 서버에서 그 줄을 직접 지우세요. 지울 줄은 `cert-authority,principals="m-…"` 부분으로 시작해요.

## 컴퓨터

컴퓨터의 에이전트는 컴퓨터가 제거됐다는 것을 바로 알고, 자기 키를 지운 뒤 멈춰요. 그 키는 다시는 작동하지 않으니, 유출된 키라도 컴퓨터를 제거하는 순간 쓸모없어져요. 절전 모드였거나 오프라인이었던 컴퓨터는 다음에 에이전트가 연결될 때 알게 돼요.

컴퓨터를 다시 연결하려면 **머신 추가**에서 **컴퓨터**를 고르세요. 설치 스크립트가 새 키를 만들고, 컴퓨터는 새 머신으로 다시 나타나요.

에이전트 자체는 직접 제거할 때까지 컴퓨터에 남아 있어요:

```sh title="컴퓨터에서"
~/.tterm-web/uninstall.sh
```

이 스크립트는 에이전트의 자동 시작 설정과, 컴퓨터 키를 포함한 `~/.tterm-web` 전체, 그리고 tTerm의 터미널이 `~/.tterm`에 넣어 둔 셸 스크립트를 지워요. 같은 `~/.tterm`에 있는 tTerm 봇의 에이전트는 남아요. 이 스크립트만으로는 tTerm Web에서 컴퓨터가 제거되지 않아요. 직접 제거할 때까지 tTerm Web 목록에 그대로 남아 있어요.

## Mac용 tTerm을 쓰는 Mac

로그인한 [Mac용 tTerm](../../local/mac/)은 에이전트 대신 직접 이 Mac과 tTerm Web의 연결을 맡아요. 이 연결은 **설정** → **이 컴퓨터**에 있는 스위치 **tTerm Web과 휴대폰에서 열기**로 켜고 꺼요. 켜 두면 Mac에서 tTerm이 실행되는 동안 tTerm Web과 휴대폰에서 이 Mac의 터미널을 열 수 있어요. 끄면 tTerm Web에서는 이 Mac이 오프라인으로 표시되고, 앱에서는 모든 게 전과 같이 작동해요. tTerm Web에서 이 Mac에 연 터미널은 확인을 거친 뒤 종료돼요.

Mac도 다른 컴퓨터와 똑같이 tTerm Web에서 제거해요. 그러면 **이 컴퓨터**에 이렇게 표시돼요: **이 Mac은 tTerm Web에서 제거되어 거기서 열 수 없어요. 다시 추가하려면 이 설정을 켜세요.**

앱도 기기 중 하나예요. **설정** → **기기**에서 **지우기**를 누르면 앱이 로그아웃되고, 이 Mac에서만 작동하게 돼요. [기기와 로그인](../../account/devices/)을 참고하세요.

:::note[터미널 종료는 머신 제거가 아니에요]
사이드바나 검색에서 터미널을 종료하면, 확인을 거친 뒤 그 셸 하나만 종료돼요. 머신은 남고, 머신의 다른 터미널도 그대로예요.
:::
