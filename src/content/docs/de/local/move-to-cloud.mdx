---
title: Umzug in die Cloud
description: In tTerm für Mac bringt der Umzug in die Cloud die Server, die du mit ssh erreichst, in dein Konto, damit sie sich in jedem Browser und auf deinem Handy öffnen.
---

Die Server, die du von deinem Mac aus mit `ssh` erreichst, können sich auch in tTerm Web öffnen, auf deinem Handy oder auf jedem Computer, an dem du dich anmeldest. **Umzug in die Cloud** in [tTerm für Mac](../mac/) bringt sie in dein Konto, jeden auf die Art, die du für ihn wählst. Nichts zieht um, bis du auf **Umziehen** drückst.

## Wo du das findest

Melde dich in tTerm für Mac an, öffne unten in der Seitenleiste das Kontomenü und wähl **Umzug in die Cloud**, direkt über **Abmelden**. Auch **⌘K** findet den Punkt.

## Was gefunden wird

Die **Server auf diesem Mac** stammen aus `~/.ssh/config`, `known_hosts` und den `ssh`-Befehlen, die du in den Terminals von tTerm auf diesem Mac ausgeführt hast. Für jeden liefert `ssh -G` Adresse, Port, Benutzer, Schlüssel und Bastion-Host, so wie ssh selbst sie verwenden würde; Benutzer und Port, die du selbst eingegeben hast, etwa mit `ssh root@host` oder `-p 2222`, ersetzen die Angaben aus der Config. Der Mac verbindet sich dafür mit keinem der Server.

Angehakt sind alle Server außer einem git-Host wie github.com (**Ein Git-Host: kein Terminal zum Öffnen**), einem Server mit dem Vermerk **Schon in tTerm**, einem, den nur `known_hosts` kennt, und einem, für den du auf der [Leiste](#die-leiste-nach-ssh) **Bei … nicht mehr fragen** gewählt hast. Danach prüft tTerm Web aus der Cloud, ob es sich mit dem SSH-Port jedes Servers verbinden kann oder mit dem seines Bastion-Hosts.

Unter den Servern listet **Schlüssel in ~/.ssh** deine privaten Schlüssel auf. Nur die angehakten kommen in deinen Tresor. Ein Schlüssel wird von selbst angehakt, wenn sich ein angehakter Server über **Mein Schlüssel** mit ihm öffnet.

## Drei Wege auf den Server

Für jeden Server wählst du einzeln:

- **Mein Schlüssel** – der Schlüssel wird auf diesem Mac verschlüsselt und kommt in deinen Tresor, und auf dem Server ändert sich nichts. tTerm Web meldet sich aus der Cloud an, und ein Gerät von dir mit geöffnetem Tresor signiert die Anmeldung: ein Browser, in dem du den Tresor geöffnet hast, oder dieser Mac. Passt für einen Server, den tTerm Web erreicht, mit einem Schlüssel in `~/.ssh`, der umziehen kann. Mehr dazu unter [Dein Tresor für SSH-Schlüssel](../../security/keys/).
- **tTerm-Zugang** – dieser Mac meldet sich einmal an und fügt die eigene Zeile von tTerm in `~/.ssh/authorized_keys` des Benutzers ein, als der er sich anmeldet; dein Schlüssel bleibt hier. Ab dann meldet sich tTerm als dieser Benutzer mit einem Zertifikat an, das zwei Minuten lebt, wie bei einem [Server, der mit einem Befehl verbunden ist](../../machines/servers/), und braucht keinen Tresor. Auf der Leiste nach `ssh` heißt dieser Weg **tTerm Zugang geben**.
- **Über diesen Mac** – nichts zieht um: tTerm bittet diesen Mac, `ssh` zum Server auszuführen, solange der Mac eingeschaltet ist. Passt für einen Server hinter einem VPN oder in einem privaten Netzwerk, den tTerm Web nicht erreicht, und für einen, dessen Schlüssel diesen Mac nicht verlassen kann. Sein Terminal läuft im klassischen Modus: Jede Taste geht direkt an ssh auf dem Mac, ohne Blöcke und ohne Rückfrage vor einem gefährlichen Befehl.

tTerm wählt für jeden Server vor: **Mein Schlüssel**, wo sein Schlüssel umziehen kann, **Über diesen Mac**, wo tTerm Web den Server nicht erreicht oder sein Schlüssel den Mac nicht verlassen kann, sonst **tTerm-Zugang**. Ein Server, den tTerm Web nicht erreicht, hat nur **Über diesen Mac**. Ein Server hinter einem Bastion-Host, den die Cloud erreicht, öffnet sich über diesen Bastion-Host.

:::note[Für „Über diesen Mac“ muss der Mac online sein]
Aktiviere in tTerm für Mac **Einstellungen** → **Dieser Computer** → **Für tTerm Web und dein Handy öffnen**. tTerm bleibt dann bei geschlossenem Fenster in der Menüleiste und startet, wenn du dich anmeldest.
:::

## Wenn du auf „Umziehen“ drückst

Der Button zählt die angehakten Server: **3 Server umziehen**.

- **Mein Schlüssel** braucht deinen Tresor. Drück beim ersten Mal auf **Tresor mit Touch ID erstellen** und bewahre den [Wiederherstellungscode](../../security/keys/#der-wiederherstellungscode) auf. Ein gesperrter Tresor fragt nach Touch ID oder dem Passwort deines Macs oder, auf einem Mac, der ihn noch nicht selbst öffnen kann, einmal nach dem Wiederherstellungscode.
- Hat ein Schlüssel eine Passphrase, fragt tTerm einmal danach. Die Passphrase bleibt auf diesem Mac.
- Bei **Mein Schlüssel** meldet sich dieser Mac zuerst nur mit diesem Schlüssel beim Server an; erst dann kommt der Schlüssel in deinen Tresor, einmal für alle seine Server. Bei **tTerm-Zugang** meldet sich dieser Mac an, um die Zeile hinzuzufügen, und tTerm meldet sich einmal mit seinem Zertifikat an, um sie zu prüfen.
- **Mein Schlüssel** und **tTerm-Zugang** brauchen den Host-Schlüssel des Servers in `known_hosts`: Verbinde dich mit einem neuen Server vorher einmal von diesem Mac aus.

Für einen Server, bei dem es fehlschlägt, wird nichts gespeichert. Ein Schlüssel, der nur für fehlgeschlagene Server in den Tresor kam, wird wieder daraus entfernt, und eine Zeile, die tTerm auf einem solchen Server hinzugefügt hat, wird wieder gelöscht.

## Nach dem Umzug

Das Ergebnis zeigt, wie viele Server jetzt in tTerm sind, alle in Personal: **2 von 3 Servern in tTerm übernommen**. Jede Zeile sagt, wie sich ihr Server öffnet: **Öffnet sich mit deinem Schlüssel**, **Öffnet sich mit dem tTerm-Zugang** oder **Über diesen Mac, solange er eingeschaltet ist**. Daneben öffnet **Terminal öffnen** dort ein Terminal. Bei einem fehlgeschlagenen Server steht, warum, dazu **Erneut versuchen** und **Ändern**: **Ändern** führt zurück zur Liste, in der nur dieser Server angehakt ist. Ganz unten stehen die Schlüssel, die jetzt in deinem Tresor sind, oder **Kein Schlüssel ist umgezogen: Deine Schlüssel bleiben auf diesem Mac.**

In der Seitenleiste hat ein Server, der sich mit deinem Schlüssel öffnet, ein Schlüsselsymbol hinter seinem Namen, und einer, der über deinen Mac läuft, zeigt **via Mac**.

## Die Leiste nach ssh

Wenn `ssh` in einem Terminal dieses Macs ohne Fehler endet, kann unter seinem Block eine Leiste erscheinen: **droplet: von überall öffnen**, mit der Adresse und deinem Schlüssel.

- **Schlüssel speichern** – dasselbe wie **Mein Schlüssel**, wenn der Schlüssel umziehen kann.
- **tTerm Zugang geben** – dasselbe wie **tTerm-Zugang**.
- **Nicht jetzt** oder **Bei droplet nicht mehr fragen**.

Für einen Server, den tTerm Web nicht erreicht, bietet die Leiste stattdessen **Über diesen Mac öffnen** an. Sie erscheint für jeden Server einmal und nie für einen git-Host oder einen Server, der schon in tTerm ist. Ein Server, den du über die Leiste speicherst, kommt ebenfalls in Personal.
