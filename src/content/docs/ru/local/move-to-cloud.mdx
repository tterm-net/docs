Серверы, на которые ты ходишь с Mac по `ssh`, могут открываться из tTerm Web, с телефона или с любого компьютера, где ты входишь в аккаунт. «Перенести в облако» в [tTerm для Mac](../mac/) переносит их в твой аккаунт, каждый тем способом, который ты для него выберешь. Пока ты не нажмёшь «Перенести», ничего не переносится.

## Где это

Войди в tTerm для Mac, нажми на аккаунт внизу боковой панели и выбери «Перенести в облако» – пункт прямо над «Выйти». Его находит и **⌘K**.

## Что находит

«Серверы на этом Mac» берутся из `~/.ssh/config`, `known_hosts` и команд `ssh`, которые ты запускал в терминалах tTerm на этом Mac. Для каждого `ssh -G` сообщает адрес, порт, пользователя, ключи и бастион – то, что использовал бы сам ssh. Если ты набирал пользователя или порт сам, например `ssh root@host` или `-p 2222`, берутся они, а не те, что в config. Ни к одному серверу Mac при этом не подключается.

Отмечены все серверы, кроме git-хостингов вроде github.com («Git-хостинг: терминала там нет»), серверов, которые «Уже в tTerm», тех, что известны только из `known_hosts`, и тех, для которых ты выбрал «Не спрашивать про …» на [плашке](#плашка-после-ssh). Затем tTerm Web проверяет из облака, может ли он подключиться к порту SSH каждого сервера или его бастиона.

Под серверами, в «Ключи в ~/.ssh», – твои закрытые ключи. В хранилище попадут только отмеченные. Ключ отмечается сам, если им открывается отмеченный сервер со способом «Мой ключ».

<Screenshot name="move-found" alt="«Перенести в облако»: отмечены web-01, staging и backup, у каждого свой способ входа, staging «через этот Mac», раз облако до него не достаёт; db-1 «Уже в tTerm» и github.com, git-хостинг, не отмечены; «Ключи в ~/.ssh» с отмеченным id_ed25519; «Перенести 3 сервера»." />

## Три способа входа

У каждого сервера свой выбор:

- «Мой ключ» – ключ шифруется на этом Mac и попадает в хранилище, а сервер остаётся как есть. tTerm Web входит на сервер из облака, а вход подписывает твоё устройство с открытым хранилищем: браузер, где ты открыл хранилище, или этот Mac. Подходит для сервера, доступного из облака, с ключом из `~/.ssh`, который можно перенести. Подробно в разделе [Хранилище ключей](../../security/keys/).
- «Пропуск tTerm» – этот Mac один раз входит на сервер и добавляет строку tTerm в `~/.ssh/authorized_keys` того пользователя, под которым входит; твой ключ остаётся здесь. Дальше tTerm входит под этим пользователем по сертификату, который живёт две минуты, как и на [сервер, подключённый одной командой](../../machines/servers/), и хранилище для этого не нужно. На плашке после `ssh` этот способ называется «Впустить tTerm».
- «Через этот Mac» – ничего не переносится: tTerm просит этот Mac запустить `ssh` до сервера, пока Mac включён. Подходит для сервера за VPN или в частной сети, недоступного для tTerm Web, и для сервера, чей ключ не может покинуть этот Mac. Терминал такого сервера работает в классическом режиме: каждая клавиша идёт прямо в ssh на Mac, блоков нет, и tTerm не переспрашивает перед опасными командами.

<Screenshot name="move-ways" alt="У каждого сервера свой способ входа: web-01 – «Мой ключ», staging – «Через этот Mac», у backup открыт выбор: «Мой ключ», «Пропуск tTerm», «Через этот Mac»; ниже – что значит каждый." />

tTerm сам выбирает для каждого сервера: «Мой ключ», если ключ можно перенести, «Через этот Mac», если сервер недоступен для tTerm Web или ключ не может покинуть Mac, а иначе «Пропуск tTerm». Для недоступного сервера есть только «Через этот Mac». Сервер за бастионом, доступным из облака, открывается через этот бастион.

:::note[«Через этот Mac» работает, пока Mac на связи]
Включи в tTerm для Mac «Настройки» → «Этот компьютер» → «Доступ из tTerm Web и с телефона». Тогда tTerm остаётся в строке меню с закрытым окном и запускается при входе в систему.
:::

## Когда нажмёшь «Перенести»

Кнопка считает отмеченные серверы: «Перенести 3 сервера».

- Для способа «Мой ключ» нужно хранилище. В первый раз нажми «Создать хранилище с Touch ID» и сохрани [код восстановления](../../security/keys/#код-восстановления). Заблокированное хранилище попросит Touch ID или пароль Mac, а если у этого Mac ещё нет его замка, один раз код восстановления.
- Для ключа с парольной фразой tTerm один раз спросит её. Фраза остаётся на этом Mac.
- Со способом «Мой ключ» этот Mac сначала входит на сервер только этим ключом, и лишь потом ключ попадает в хранилище, один раз для всех своих серверов. Со способом «Пропуск tTerm» Mac входит, чтобы добавить строку, а tTerm один раз входит по своему сертификату, чтобы её проверить.
- «Мой ключ» и «Пропуск tTerm» требуют ключ хоста сервера в `known_hosts`: на новый сервер сначала один раз зайди с этого Mac.

<Screenshot name="move-vault" alt="Первый перенос с «Моим ключом»: «Сохранить ключ в хранилище», id_ed25519 попадёт в хранилище, которое открывается как разблокируется этот Mac; «Отменить» и «Создать хранилище с Touch ID»." />

Для сервера, который не удалось перенести, ничего не сохраняется. Ключ, попавший в хранилище только ради таких серверов, снова убирается из него, а строка, которую tTerm добавил на такой сервер, снимается.

## После переноса

Итог говорит, сколько серверов теперь в tTerm, все в проекте Personal: «2 из 3 серверов теперь в tTerm». В строке каждого сервера сказано, как он открывается: «Открывается твоим ключом», «Открывается по пропуску tTerm» или «Через этот Mac, пока он включён». Рядом – «Открыть терминал». В строке сервера, который не удалось перенести, сказано почему, а рядом «Повторить» и «Изменить»: «Изменить» вернёт к списку, где отмечен только этот сервер. Внизу – какие ключи теперь в хранилище, или «Ни один ключ не перенесён: твои ключи остаются на этом Mac.»

В боковой панели у сервера, который открывается твоим ключом, после имени стоит значок ключа, а у сервера через Mac – «через Mac».

<Screenshot name="move-result" alt="«2 из 3 серверов теперь в tTerm»: web-01 «Открывается твоим ключом», staging «Через этот Mac, пока он включён», у обоих «Открыть терминал»; backup не перенесён (нет ключа хоста в known_hosts), «Повторить» и «Изменить»; id_ed25519 в хранилище. ## Плашка после ssh

Когда `ssh` в терминале этого Mac завершается без ошибки, под его блоком может появиться плашка «droplet: открывай откуда угодно» с адресом и твоим ключом.

<Screenshot name="move-strip" alt="Под блоком ssh droplet в терминале этого Mac: «droplet: открывай откуда угодно» с адресом root@203.0.113.20 и ключом ~/.ssh/id_ed25519; «Сохранить мой ключ», «Впустить tTerm», «Не сейчас», «Не спрашивать про droplet»." />

- «Сохранить мой ключ» – то же, что «Мой ключ», если ключ можно перенести.
- «Впустить tTerm» – то же, что «Пропуск tTerm».
- «Не сейчас» или «Не спрашивать про droplet».

Если сервер недоступен для tTerm Web, плашка вместо этого предложит «Открывать через этот Mac». Она появляется для каждого сервера один раз и никогда для git-хостингов и серверов, которые уже в tTerm. Сервер с плашки тоже попадает в Personal.
