服务器通过普通的 SSH 连接，只需一条命令。我们不保存任何密钥：每次连接，我们都会单独签发一张证书，它只有两分钟有效期，并且只对这台服务器有效。

如果你的 Mac 已经能通过 SSH 连接这台服务器，它可以和其他服务器一起一次迁移过来，不需要在服务器上运行任何东西：参见[迁移到云端](../../local/move-to-cloud/)。

## 连接服务器

<Steps>

1. 在 tTerm Web 中打开**添加机器**，选择**服务器**。

   <Screenshot name="add-server" alt="“添加机器”窗口，已选择“服务器”：要在服务器上运行的一次性命令，带有“复制”按钮，tTerm Web 正在等待服务器。" />

2. 复制命令，在服务器上以 root 或任何有 sudo 权限的用户身份运行：

   ```sh title="在服务器上"
   curl -sSL https://connect.tterm.net/s/<token> | sudo sh
   ```

3. 脚本一完成，服务器就会出现在项目中，通常不超过一分钟。云端会自行登录服务器，检查它，并读取这台机器的信息：系统、地址和 shell。

</Steps>

:::caution[命令只能使用一次]
它只能使用一次，在接下来的 10 分钟内有效。过期了？点击**获取新命令**。
:::

## 这个脚本会做什么

- 创建没有密码的用户 `tterm`。如果我们的 Telegram 机器人已经创建过这个用户，就直接沿用。
- 允许云端以 `tterm` 的身份登录，所用证书只有两分钟有效期，并且只为这台服务器签发。服务器上不会留下任何密钥。
- 给 `tterm` 授予 sudo 权限，以便你管理服务器。一条命令即可收回。
- 绝不改动 `sshd_config`，也不开放任何端口。重复运行也是安全的。

信任关系只是用户 `tterm` 的 `authorized_keys` 中的一行，每台服务器都有自己的一行：

```text title="~tterm/.ssh/authorized_keys"
cert-authority,principals="m-…" ssh-ed25519 AAAAC3NzaC1lZDI1NTE5… tterm-web ca-…
```

:::tip[位于 NAT 之后，或无法从外部 SSH 访问的服务器]
云端通过 SSH 登录服务器，所以服务器的 SSH 端口必须能从外部访问。如果不能，就像在[电脑](../computers/)上那样，在服务器上安装代理：这样连接就会从内部发起。
:::

## 移除服务器

在项目页面上，点击服务器旁的 ⋯，选择**移除机器**。云端将不再登录这台服务器，并会在服务器上收回自己的访问权限。如果服务器没有响应，接下来会给出完成这一步的命令。详见[移除机器](../remove/)。

安装程序设置的其他内容如何清除，写在脚本本身的开头。
