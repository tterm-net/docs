---
title: 迁移到云端
description: 在 tTerm Mac 版中，“迁移到云端”会把你用 ssh 连接的服务器迁移到你的账号，让它们可以从任何浏览器和手机上打开。
---

你在 Mac 上用 `ssh` 连接的服务器，也可以从 tTerm Web、手机或你登录的任何电脑上打开。[tTerm Mac 版](../mac/)中的**迁移到云端**会把它们迁移到你的账号，每台服务器都按你为它选择的方式迁移。在你点击**迁移**之前，什么都不会迁移。

## 在哪里

登录 tTerm Mac 版，点击侧边栏底部的账号，选择**迁移到云端**，它就在**退出登录**的正上方。用 **⌘K** 也能找到它。

## 它会找到什么

**这台 Mac 上的服务器**来自 `~/.ssh/config`、`known_hosts`，以及你在这台 Mac 上的 tTerm 终端中运行过的 `ssh` 命令。对每台服务器，`ssh -G` 会给出 ssh 自己会使用的地址、端口、用户、密钥和跳板机；你输入的用户和端口，比如 `ssh root@host` 或 `-p 2222`，会取代配置文件中的设置。在这个过程中，Mac 不会连接任何一台服务器。

所有服务器默认都已勾选，但以下几种除外：github.com 这样的 git 托管平台（**git 托管平台：没有可打开的终端**）、显示**已在 tTerm 中**的服务器、只出现在 `known_hosts` 中的服务器，以及你在[提示条](#ssh-之后的提示条)上选择了**不再为 … 询问**的服务器。然后，tTerm Web 会从云端检查能否连接到每台服务器的 SSH 端口，或其跳板机的 SSH 端口。

在服务器下方，**~/.ssh 中的密钥**列出了你的私钥。只有勾选的密钥才会存入你的保险库。如果某台已勾选的服务器以**我的密钥**方式用某个密钥打开，这个密钥会被自动勾选。

## 三种连接方式

每台服务器都可以单独选择：

- **我的密钥**：密钥在这台 Mac 上加密后存入你的保险库，服务器保持原样。tTerm Web 从云端登录，由你的一台已打开保险库的设备为这次登录签名：可以是你打开了保险库的浏览器，也可以是这台 Mac。适用于 tTerm Web 能连接到、密钥在 `~/.ssh` 中并且可以迁移的服务器。详见[你的 SSH 密钥保险库](../../security/keys/)。
- **tTerm 通行证**：这台 Mac 登录一次，在它所登录用户的 `~/.ssh/authorized_keys` 中添加 tTerm 自己的一行；你的密钥留在这里。此后，tTerm 以这个用户的身份、用两分钟有效的证书登录，就像在[用一条命令连接的服务器](../../machines/servers/)上一样，不需要保险库。在 `ssh` 之后出现的提示条上，这种方式叫作**允许 tTerm 登录**。
- **通过这台 Mac**：什么都不迁移。在这台 Mac 开机期间，tTerm 会请它运行 `ssh` 连接服务器。适用于位于 VPN 之后或私有网络中、tTerm Web 无法连接的服务器，以及密钥无法离开这台 Mac 的服务器。它的终端以经典模式运行：每个按键都直接发送给 Mac 上的 ssh，没有块，运行危险命令前也不会询问。

tTerm 会为每台服务器预先选好方式：密钥可以迁移的，选**我的密钥**；tTerm Web 连接不到或密钥无法离开的，选**通过这台 Mac**；其他情况选 **tTerm 通行证**。tTerm Web 连接不到的服务器只能选**通过这台 Mac**。位于跳板机之后、而云端能连接到这台跳板机的服务器，会经由它打开。

:::note[“通过这台 Mac”需要 Mac 在线]
在 tTerm Mac 版中，开启**设置** → **这台电脑** → **向 tTerm Web 和手机开放**。这样，关闭窗口后 tTerm 仍会留在菜单栏中，并在你登录系统时自动启动。
:::

## 点击“迁移”时

按钮上会显示勾选了几台服务器：**迁移 3 台服务器**。

- **我的密钥**需要你的保险库。第一次使用时，点击**用触控 ID 创建我的保险库**，并保存好[恢复代码](../../security/keys/#恢复代码)。保险库锁定时，会要求使用 触控 ID 或 Mac 的密码；如果这台 Mac 还不能自己打开保险库，则需要输入一次恢复代码。
- 如果密钥设有密码短语，tTerm 会询问一次。密码短语只留在这台 Mac 上。
- 选择**我的密钥**时，这台 Mac 会先只用这个密钥登录服务器；成功之后，密钥才会存入你的保险库，用到它的所有服务器只需存入一次。选择 **tTerm 通行证**时，这台 Mac 登录服务器添加那一行，tTerm 再用自己的证书登录一次加以验证。
- **我的密钥**和 **tTerm 通行证**都要求 `known_hosts` 中已有服务器的主机密钥：对于新服务器，请先从这台 Mac 连接一次。

迁移失败的服务器不会保存任何内容。如果某个密钥只是为了这些失败的服务器才存入保险库，它会被重新移出；tTerm 在这类服务器上添加的那一行也会被删除。

## 迁移之后

结果会显示现在有多少台服务器已加入 tTerm，它们都在 Personal 中：**3 台服务器中有 2 台已加入 tTerm**。每一行都写明了这台服务器的打开方式：**用你的密钥打开**、**用 tTerm 通行证打开**或**通过这台 Mac，在它开机时可用**。旁边的**打开终端**会在这台服务器上打开一个终端。迁移失败的服务器会显示原因，旁边有**重试**和**更改**：**更改**会回到列表，并且只勾选这一台服务器。底部显示的是现在已存入你保险库的密钥，或者**没有迁移任何密钥：你的密钥仍留在这台 Mac 上。**

在侧边栏中，用你的密钥打开的服务器，名称后面会有一个钥匙图标；通过你的 Mac 打开的服务器，则显示**通过 Mac**。

## ssh 之后的提示条

在这台 Mac 的终端中，当 `ssh` 正常结束、没有报错时，它的块下方可能会出现一个提示条：**droplet：从任何地方打开它**，并附有地址和你的密钥。

- **保存我的密钥**：与**我的密钥**相同，适用于密钥可以迁移的情况。
- **允许 tTerm 登录**：与 **tTerm 通行证**相同。
- **以后再说**，或**不再为 droplet 询问**。

对于 tTerm Web 连接不到的服务器，提示条会改为提供**通过这台 Mac 打开**。每台服务器只会出现一次提示条，git 托管平台和已在 tTerm 中的服务器则从不出现。从提示条保存的服务器同样会加入 Personal。
