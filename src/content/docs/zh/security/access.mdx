机器的访问权限很容易授予，也同样容易收回。我们不需要你的密钥，也不开放任何端口。

## 两分钟有效的证书

每次连接，我们都会单独签发一张 SSH 证书，里面写着你的名字，只对这一台服务器有效。因此，在服务器的日志中，每次登录都带有登录者的名字：

```text title="/var/log/auth.log"
Accepted publickey for tterm from 203.0.113.24 port 41522 ssh2: ED25519-CERT SHA256:… ID Anna via tTerm Web (…) to web-01 (serial 1042) CA ED25519 SHA256:…
```

## 签名独立进行

CA 密钥存放在一个不联网的独立进程中。核心程序无法读取它们，只能请求签名，每次签名都会记录在日志中。

## 不改动 sshd_config

信任关系只是一个用户 `tterm` 的 `authorized_keys` 中的一行。不需要重启任何东西，所以你不会把自己锁在服务器外面。

## 从 Mac 迁移来的服务器

从 tTerm Mac 版迁移来的服务器，还可以用另外两种方式打开。选择**我的密钥**，就用[保险库](../keys/)中你自己的密钥登录，服务器上不会添加任何东西。这次登录由打开终端的那台设备签名，用的是已在那里打开的密钥：可以是你的浏览器，也可以是 tTerm Mac 版，后者为它自己的终端签名。tTerm 不会请求其他任何设备，你的 Mac 也不例外，所以只凭邮件中的验证码登录，打不开任何一台这样的服务器。选择**通过这台 Mac**，就由你的 Mac 运行 `ssh` 连接服务器，云端完全不需要能连到它；有了保险库之后，这样的服务器和你的电脑一样，只在密钥已打开的地方才能打开：参见[密钥已打开的地方](../keys/#密钥已打开的地方)。第三种方式是 **tTerm 通行证**：同样是两分钟有效的证书，只是 tTerm 的那一行写在你自己用户的 `authorized_keys` 中，而不是 `tterm` 的。详见[迁移到云端](../../local/move-to-cloud/#三种连接方式)。

## 只由内向外连接

电脑上的代理会主动向外连接，不需要任何入站端口。卸载只需一条命令。

## 没有中间人

tTerm Web 的页面和终端直接连到我们位于欧盟的服务器。Cloudflare 只为我们提供 DNS，看不到你的命令。

## 开源

云端和代理的代码以 AGPL v3 许可证开源：[github.com/tterm-net](https://github.com/tterm-net)。安装脚本很短：运行之前先读一读。

## 收回访问权限

[移除服务器](../../machines/remove/)，云端就会在服务器上收回自己的访问权限。如果服务器没有响应，会出现一条在服务器上完成这一步的命令。从电脑上卸载代理只需一条命令：`~/.tterm-web/uninstall.sh`。要从保险库中移除你的某个密钥，在**设置** → **密钥**中点击**移除**。
