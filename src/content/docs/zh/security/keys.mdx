保险库存放你自己的 SSH 密钥，供你用这些密钥连接的服务器使用。密钥在离开你的设备之前就已在设备上加密，只有你能打开保险库：在任意浏览器中用你的保险库密码打开，在你保存了密钥的设备上则无需密码。tTerm 保存的是加密后的密钥，以及每个密钥的公钥和指纹：它无法打开保险库，也无法读取任何密钥。保险库位于**设置** → **密钥**。

## 服务器如何用你的密钥打开

如果你从 [tTerm Mac 版](../../local/mac/)以**我的密钥**方式迁移了一台服务器，或在 `ssh` 之后的提示条上点击了**保存我的密钥**，这台服务器就会用你的密钥打开：参见[迁移到云端](../../local/move-to-cloud/)。当你在这台服务器上打开终端时，这次登录由你打开终端的那台设备签名，用的是已在那里打开的密钥：可以是你的浏览器，也可以是 tTerm Mac 版，后者为它自己的终端签名。tTerm 不会请求其他任何设备，你的 Mac 也不例外。设备只用这个密钥为 SSH 登录签名，不签任何别的东西，密钥也从不离开这台设备。tTerm 在使用签名之前，会先用密钥的公钥核验它。

## 创建保险库

<Tabs>
	<TabItem label="在浏览器中">

在**设置** → **密钥**中，点击**从文件添加密钥**，选择你的私钥，也就是不带 `.pub` 的那个文件。如果密钥设有密码短语，输入它并点击**打开密钥**：密码短语只在这个浏览器中用来打开密钥，不会发往任何地方。给密钥起个名字，然后点击**下一步**。

在**创建保险库密码**窗口中，输入两次密码，然后点击**创建保险库**。接着，在能用通行密钥保存密钥的浏览器中，tTerm 会询问是否把你的密钥保存在这里，和[在其他浏览器中打开](#在其他浏览器中打开)时一样。

	</TabItem>
	<TabItem label="在 tTerm Mac 版中">

第一次保存密钥时会创建保险库：通过“迁移到云端”，或在 `ssh` 之后的提示条上点击**保存我的密钥**。在**创建保险库密码**窗口中，输入两次密码，然后点击**创建保险库**：这一步不需要触控 ID。从此，这台 Mac 就能自己打开保险库，用触控 ID 或 Mac 的密码即可。

	</TabItem>
</Tabs>

### 保险库密码

保险库密码在创建保险库时由你自己设定：至少 12 个字符，由几个单词组成的短语最简单。密码还不够长时，窗口会显示还差几个字符。也可以使用 A 到 Z 以外的文字，但国外的电脑上可能没有相应的输入法。

<Screenshot name="vault-password" alt="“创建保险库密码”：id_ed25519 会先在这个浏览器中加密，再存入你的保险库，用这个密码可在任意浏览器中打开它。“密码”和“确认密码”中的输入显示为圆点，旁边有“显示”，提示至少 12 个字符，并显示“密码一致”；tTerm 不知道这个密码，也无法找回它；“取消”和“创建保险库”。" />

密码本身不会发往任何地方：你的浏览器或 Mac 会用它生成一个密钥，而 tTerm 只会把你经过加密的保险库密钥交给能证明自己知道密码的设备。tTerm 不知道这个密码，也无法找回它：请把它保存在你的密码管理器中。

密码输错时，窗口会提示，并显示还剩几次机会。一小时内输错十次后，要等一小时才能再试；一天内输错三十次后，要等到这一天结束。窗口会告诉你什么时候可以再试。

**忘记密码了？** 在无需密码就能打开保险库的地方设置新密码：在你的 Mac 上，打开 tTerm Mac 版的**设置** → **密钥** → **更改密码**，用触控 ID 确认；或者在保存了你密钥的浏览器中，同样是在**设置** → **密钥**中。如果没有这样的设备，保险库中的密钥就再也无法打开了，tTerm 也打不开。密钥本身通常还留在你的 Mac 上，在 `~/.ssh` 中。

<Screenshot name="vault-forgot" alt="“忘记保险库密码了？”：tTerm 无法告诉你这个密码，但可以在无需密码就能打开保险库的地方设置新密码：在你 Mac 上的 tTerm Mac 版中（“设置”›“密钥”›“更改密码”，用触控 ID），或在保存了你密钥的浏览器中；如果没有这样的设备，这些密钥就再也无法打开了；“知道了”。" />

## 在其他浏览器中打开

在没有保存你密钥的浏览器中，**设置** → **密钥**会显示**你的保险库已关闭**，并有一个**保险库密码**输入框。用你的密钥打开的服务器，会在创建终端之前，先在它的卡片上显示同样的输入框：参见[等待保险库的服务器](#等待保险库的服务器)。

<Screenshot name="vault-open" alt="在从未打开过保险库的浏览器中，“设置”→“密钥”：“你的保险库已关闭”，只有你的保险库密码能打开这些密钥，而且就在这个浏览器中打开；“保险库密码”输入框中的密码显示为圆点，旁边是“显示”，然后是“打开密钥”，其下方是“忘记密码了？”。再往下是“保险库密码”一行、两个密钥，以及无需密码即可打开保险库的地方。" />

- **输入保险库密码**，然后点击**打开密钥**。密钥会直接在这个浏览器中打开。
- **在 tTerm Mac 版中批准**，在别人的电脑上用这种方式很方便：无需在那里输入密码。如果你的保险库能在某台 Mac 的 tTerm Mac 版中打开，输入框下方会有**在 MacBook-Pro 上批准**，显示的是那台 Mac 的名称：点击它，**在这个浏览器中打开你的密钥**窗口就会立即向那台 Mac 发出请求。Mac 上会弹出一个窗口，说明是哪个浏览器在请求、它何时登录、从哪个地址登录。两边屏幕上会显示同样的六位数字：只有数字一致时，才点击**用触控 ID 允许**。**不是我**会结束那个浏览器的登录，**设置** → **设备**会显示还需要检查什么。请求的有效期为五分钟。**改为输入密码**会带你回到输入框。

在能用通行密钥保存密钥的浏览器中，tTerm 接着会询问是否把你的密钥保存在这里，这样下次在那里就不必输入密码：点击**用触控 ID 保存**（或者 Windows Hello、通行密钥）；如果这不是你自己的电脑，就点击**仅此一次**，这样关闭标签页时密钥就会关闭，一段时间不用，它们也会自动关闭。

<Screenshot name="vault-keep" alt="输入保险库密码之后：“你的密钥已在这个浏览器中打开”。可以用触控 ID 把它们保存在这里，这样下次只需触控 ID；如果用的是别人的电脑，则选择“仅此一次”；按钮是“仅此一次”和“用触控 ID 保存”。" />

在 tTerm Web 0.1.26 之前创建、还没有设置密码的保险库，打开方式和以前一样：在**设置** → **密钥**中点击**打开**，会弹出**在这个浏览器中打开你的密钥**窗口，其中有用于请你的 Mac 批准的**请它在这里打开你的保险库**，以及**恢复代码**和**打开**。

在 tTerm Mac 版中，还不能自己打开你保险库的 Mac——第二台 Mac、保险库是在浏览器中创建的，或者你退出后又重新登录——会显示**这台 Mac 还不能自己打开你的保险库**，要用保险库密码打开一次，无需触控 ID。此后，在那台 Mac 上用触控 ID 或 Mac 的密码就能打开它。

## 密钥已打开的地方

有了保险库之后，你的电脑、用你的密钥打开的服务器以及通过你的 Mac 打开的服务器，只在你亲自打开了密钥的设备上才能打开：用保险库密码，在保存了密钥的浏览器中用触控 ID，或者在 tTerm Mac 版中批准。你的电脑指的是装有 tTerm 代理的机器（macOS 或 Linux），以及每台装有 tTerm Mac 版的 Mac。对它们来说，用邮件中的验证码登录 tTerm 是不够的，所以进入了你邮箱的人得不到它们的任何内容，即使你的 Mac 正开着、保险库也在上面打开着。带有 tTerm 自己那一行的服务器——用一条命令连接的，或以 **tTerm 通行证**方式迁移的——不在此列：对它来说，登录就够了。如果没有保险库，或者保险库既没有密码也没有密钥，就不会有任何东西以这种方式关闭。

在密钥没有打开的设备上，这样一台机器的 **+** 会换成锁形图标，它的终端和日志都显示为灰色，各带一个锁形图标，它们的标签页也以锁形图标开头。它的任何内容都不会到达这台设备：它的终端显示的内容不会，它在搜索和输入行历史记录中的命令不会，它的日志也不会。点击锁形图标、某个终端或日志，它的标签页中会出现一张卡片，说明它为什么关闭，并就在那里按这台设备的方式打开你的密钥：**保险库密码**输入框，在保存了你密钥的浏览器中是**用触控 ID 打开**，或者**在 MacBook-Pro 上批准**。然后：

<Screenshot name="closed-sidebar" alt="在 Anna 的密钥没有打开的设备上，侧边栏中 MacBook-Pro、web-01 和 staging 的 + 换成了锁图标，它们的终端 shop 和 deploy 以及各自的日志都呈灰色，各带一个锁图标；Client X 中的 db-1 则一切如常。鼠标停在 web-01 的锁图标上：“这台设备上的密钥没有打开。打开”。" />

- 锁形图标：这台机器上的一个新终端会在卡片的位置打开；
- 已在运行的终端：终端会从它现在的位置显示出来，不会新建终端；
- 日志：日志会打开。

<Screenshot name="closed-terminal" alt="带锁图标的标签页 P/web-01 · deploy：“这个终端在这台设备上已关闭”。web-01 上的 deploy 正在运行，但在这里打开密钥之前，这里看不到它；打开之后，它会从现在的位置显示出来。下面是“保险库密码”“打开密钥”和“或在 MacBook-Pro 上批准 · 忘记密码了？”。" />

在**机器**页面上，这样的机器会显示**在这台设备上已关闭**；在项目页面上，它的每个终端在原本显示目录的位置也会这样显示。在这两个页面上，新建终端的按钮都带有锁形图标，终端也都显示为灰色。**移除**和**移到其他项目**会先就在它们的窗口中打开你的密钥：密钥打开后，才会出现红色的**移除 web-01** 和移动机器的按钮。

<Screenshot name="closed-machines" alt="在密钥没有打开的设备上，“机器”页面中 MacBook-Pro、web-01 和 staging 都标有“在这台设备上已关闭”，它们的“打开终端”带有锁图标，终端 P/MacBook-Pro · shop 和 P/web-01 · deploy 呈灰色，各带一个锁图标；Client X 中的 db-1 则一切如常。每台机器都有“移除”。" />

无论你用哪种方式打开密钥，它们随后都会在这台设备上打开所有这样的机器，而且只会创建你要求的那个终端。一个锁形图标一次只请求一个终端：点击另一个锁形图标，它的卡片会取代前一张卡片；被其他标签页挡在后面的卡片，会在密钥打开时关闭，不会创建终端。当密钥在这里关闭时（参见[何时重新锁定](#何时重新锁定)），锁形图标会立即重新出现，这些终端的标签页会变回它们的卡片；终端本身则继续在云端运行。

当你更改保险库密码，或从保险库中移出一个密钥时，你的其他设备会重新打开密钥：用保险库中的某个密钥自动完成；保险库中没有密钥时，则用新密码打开。你做出更改的那台设备保持原样。

在 tTerm Mac 版中，这台 Mac 自己的终端和通过它打开的服务器，和以前一样无需密钥就能打开；你的其他电脑和用你的密钥打开的服务器，要等保险库在那里用触控 ID 或 Mac 的密码打开之后，才能打开。你的 Mac 只为它自己用你的密钥登录服务器：浏览器要先在它自己那里打开你的密钥，才能打开这样的服务器。

## 何时重新锁定

- **在浏览器中**：8 小时没有任何操作后、关闭或重新加载 tTerm Web 时、退出登录时，以及在**设置** → **密钥**中点击**锁定**时。
- **在 tTerm Mac 版中**：只要 tTerm 在运行，保险库就会一直打开，直到你点击**锁定**或退出登录。退出登录还会让这台 Mac 无法再自己打开保险库：重新登录后，它要用你的保险库密码打开一次保险库。

## 设置 → 密钥

这个分区的顶部会显示保险库在这里是否已打开、是怎样打开的，以及何时会重新锁定。下方的**保险库密码**会显示密码是何时设置的，旁边是**更改密码**。每个密钥占一行：名称、类型和简短指纹；它**可打开**哪些服务器，或者**还没有服务器用它打开**；它是何时从 Mac 保存或从文件添加的；以及上次使用的时间，或者**尚未使用**。

<Screenshot name="keys" alt="“设置”→“密钥”：保险库“已在这个浏览器中打开”，用的是触控 ID，旁边是“锁定”；“保险库密码”可在任意浏览器中打开密钥，于今天设置，旁边是“更改密码”；两个密钥及其类型和简短指纹；“从文件添加密钥”；以及无需密码即可打开保险库的地方：Chrome on macOS。" />

- **更改密码**会设置一个新密码，新密码会立即取代旧密码：旧密码将无法再打开你的密钥。你的 Mac 和保存了你密钥的浏览器仍会照常打开它们。在保存了你密钥的浏览器中，更改时需要触控 ID（或者 Windows Hello、你的通行密钥）；在没有保存的浏览器中，需要输入当前密码；在 tTerm Mac 版中，需要触控 ID。
- **移除**会在确认后把密钥移出你的保险库，tTerm 会删除它的加密副本。用它打开的服务器仍留在 tTerm 中，但无法再打开。密钥本身仍留在原处：你的 Mac 上，或它的文件中。和对保险库的任何更改一样，这只能在密钥已打开的地方进行；在其他地方，tTerm 会提示这一点。
- **从文件添加密钥**在浏览器中提供。在 tTerm Mac 版中，密钥来自“迁移到云端”和 `ssh` 之后的提示条。

在密钥列表下方，这个分区会列出无需密码就能打开保险库的地方，也就是保存了你密钥的每台 Mac 和每个浏览器：**无需密码即可在以下设备上打开你的保险库：MacBook-Pro · tTerm Mac 版和 Chrome on macOS。在其他任何浏览器中，需用保险库密码打开。** 如果没有任何设备保存它们，则显示**你的保险库只能用保险库密码打开：目前还没有设备保存它。**

在 tTerm Web 0.1.26 之前创建、还没有设置密码的保险库，顶部会显示**设置保险库密码**：点击**设置密码**即可设置一个，之后恢复代码将会失效。在没有保存你密钥的浏览器中，设置密码需要输入你的恢复代码。

### 可以保存哪些密钥

Ed25519、ECDSA P-256 和 P-384，以及 RSA。不能保存 DSA 和 ECDSA P-521 密钥，也不能保存存放在安全密钥上的密钥（`sk-…`），因为它们无法从安全密钥中取出：这些密钥对应的服务器可以[通过你的 Mac](../../local/move-to-cloud/#三种连接方式) 打开。

浏览器能读取 OpenSSH 自有格式的密钥（设有密码短语的也可以），或不带密码短语的 PEM 格式密钥（PKCS#8、PKCS#1），每个文件一个密钥。设有密码短语的 PEM 文件，需要先运行 `ssh-keygen -p -f` 加文件名，把它转换为 OpenSSH 格式。tTerm Mac 版读取 OpenSSH 格式的密钥。

有些浏览器无法用 Ed25519 密钥签名。在这样的浏览器中，**设置** → **密钥**会注明这一点；使用这类密钥的服务器，可以在较新的浏览器或 tTerm Mac 版中打开。

## 等待保险库的服务器

在密钥没有打开的设备上，用你的密钥打开的服务器不再在终端中等待：点击它的锁形图标或新建终端的按钮，会先打开它的卡片，然后才创建终端。卡片上显示 **web-01 用你的密钥打开**，密钥就在卡片上打开：

- 在没有保存你密钥的浏览器中，**保险库密码**输入框就在那里：输入密码，然后点击**打开密钥和终端**。输入框下方有**在 MacBook-Pro 上批准**（显示的是你的 Mac 的名称）和**忘记密码了？**
- 在保存了你密钥的浏览器中，点击**用触控 ID 打开**、**用 Windows Hello 打开**或**用通行密钥打开**。下方的链接**或输入保险库密码**会改为显示密码输入框。
- 在 tTerm Mac 版中，点击**用触控 ID 打开**；如果这台 Mac 还不能自己打开你的保险库，就在那里输入一次保险库密码。

<Screenshot name="closed-new" alt="带锁图标的标签页“P/web-01 · 新终端”及其卡片：“web-01 用你的密钥打开”。这台设备上的密钥还没有打开；就在这里打开它们，web-01 上的新终端会立即打开。已输入的“保险库密码”显示为圆点，旁边是“显示”；然后是“打开密钥和终端”以及“或在 MacBook-Pro 上批准 · 忘记密码了？”；下方说明了哪些机器只在密钥已打开的地方才能打开。" />

对于在 tTerm Web 0.1.26 之前创建、还没有设置密码的保险库，卡片上和以前一样有**在 MacBook-Pro 上批准**（显示的是你的 Mac 的名称）或**使用恢复代码**。

随后，卡片上会短暂显示**正在这台设备上打开密钥…**，终端接着在它的位置打开。

如果密钥已在这里打开，但这台设备无法用这台服务器的密钥登录，终端仍会等待：比如这个密钥已从你的保险库中移出，或者无法在这个浏览器中打开。终端会说明原因，例如**你的保险库已在这里打开，但这个浏览器无法打开 id_ed25519。** 它会一直等下去，需要多久就等多久。一旦这台设备能够签名，终端就会显示**正在用你的密钥登录 web-01…**，然后自动打开。
